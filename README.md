# PatchWork

Patch live websites without rebuilding them. Patches are small files with a DSL, re-anchored when a site changes, verified in a real browser, released through a reverse proxy, and rolled back when visitors' browsers report errors.

Built for the GDG on Campus CRCE college round, problem 3, "PATCHWORK: Hotfix the Internet". The plan is in `docs/DESIGN.md`. The runbook for distributed training is in `docs/KAGGLE.md`.

## Layout

| Path | What it is |
|---|---|
| `crates/pw-core` | Deterministic core: snapshots, fingerprints, re-anchoring, DSL validation, conflicts, audit chain, releases |
| `crates/pw-proxy` | Reverse proxy: injects the runtime, serves manifests, takes beacons, auto-rolls back |
| `crates/pw-cli` | The `pw` binary: project commands, Playwright management, the training entry points |
| `crates/pw-train` | Synthetic data, held-out benchmark, DiLoCo coordinator, Kaggle launcher |
| `runtime/` | The in-page runtime (`runtime.js`) and visual editor (`editor.js`), the only JavaScript shipped |
| `training/` | Python: tokenizer, from-scratch model, trainer, DiLoCo worker, evaluator |
| `docs/` | `DESIGN.md` (decisions, deviations, measured results, limits), `KAGGLE.md` (runbook) |

## Quick start

```sh
cargo build -p pw-cli                      # builds ./target/debug/pw
./target/debug/pw browser install          # downloads Playwright's Chromium
./target/debug/pw --project demo init --name shop --upstream http://127.0.0.1:8080
./target/debug/pw --project demo snapshot http://127.0.0.1:8080/cart --out demo/snapshots/cart.html
./target/debug/pw --project demo edit http://127.0.0.1:8080/cart      # visual editor; Save writes a patch
./target/debug/pw --project demo check --snapshot /cart=demo/snapshots/cart.html
./target/debug/pw --project demo release --snapshot /cart=demo/snapshots/cart.html
./target/debug/pw --project demo proxy --listen 127.0.0.1:8787        # visitors go here
./target/debug/pw --project demo verify --base http://127.0.0.1:8787 --channel production
./target/debug/pw --project demo rollback --channel production
```

## Commands

- `pw init`, `pw dsl-schema`, `pw log`, `pw audit-verify`
- `pw snapshot URL --out FILE`: captures HTML and element rectangles
- `pw edit URL [--author NAME]`: visual editor (headed Chromium). Text, background, text colour, font size, classes, link target, hide, and move before or after another element. Each Save writes a draft patch with an identity assertion, and is audited under the actor
- `pw check --snapshot PAGE=FILE [--write] [--json]`: re-anchors every patch. Exit 2 if any patch is broken or ambiguous. `--write` rewrites relocated anchors and audits each one; an approved patch then needs approval again
- `pw merge --with DIR --snapshot PAGE=FILE [--write]`: conflicts between two patch sets. `--write` copies the other set's new patches in, and refuses when there are hard conflicts
- `pw review propose | approve | reject | list`: review states for patches. An approval is tied to the patch's content, so editing an approved patch withdraws it. The author cannot approve their own patch unless `--allow-self-review` is given, and that is recorded
- `pw release [--channel NAME] [--dry-run] [--accept-relocated] [--waive-verification REASON] [--waive-review REASON] --snapshot PAGE=FILE`: publishes an immutable release. Refuses heuristic relocations unless `--accept-relocated`. Protected channels (`production` by default, in `pw.toml`) also need every patch approved and a complete, passing verification of the same behaviour. `--dry-run` lists every reason a real release would be blocked. A waiver is audited with its reason
- `pw verify --base URL --channel NAME [--interact] [--no-visual]`: checks each assertion in Chromium through the proxy, compares the channel with production outside the patched elements, and writes a verification record. `--interact` runs click checks, and a click can trigger a real action, so use a copy of the site
- `pw rollback`, `pw proxy --listen ADDR`. Every command takes `--actor NAME` (or `PW_ACTOR`) for the audit trail; the default is the login name, and the name is declared, not checked
- `pw browser install [--with-deps]`, `pw browser status`
- `pw train gen-data | match-data | bench [--matcher DIR] [--matcher-grid] [--drift compound] | serve | kaggle plan | kaggle push`
- `pw train track --matcher DIR --slices 101:mixed,102:compound --grid`: chooses the combined tracker's setting on the development seeds and writes `DIR/selection.json`, bound to the weights by their SHA-256. `pw --matcher DIR` and `pw train track --matcher DIR --slices ...` then use that recorded setting, and refuse a folder with no record or with different weights. Model details and token counts are in `docs/MODELS.md`, generated by `python -m training.model_card`

## Status

Verified here:

- `cargo test --workspace` passes (unit and end-to-end tests). The end-to-end proxy test runs a real upstream, injects into gzipped HTML under a nonce CSP, and checks the rollback path.
- The CLI ran the full path in Chromium 153 through the proxy: check, release, proxy injection, manifest, and browser assertions, which confirmed that the runtime applied the patch.
- A two-round distributed run with one coordinator and three CPU workers completed.
- A Kaggle plan with placeholder accounts validates. Nothing was pushed.

Not verified or not done:

- The trained language model runs in Rust (`pw --model DIR`). It is opt-in and not recommended: on the benchmark it does not beat the heuristic (`docs/DESIGN.md`, section 6.5).
- The matcher, trained from scratch, is opt-in (`pw --matcher DIR`; the setting it uses is the one recorded in `DIR/selection.json`). Under the protocol fixed in advance it is not adopted: it relocates 90% of compound-drift targets correctly (the heuristic: 33%), but it makes more wrong matches on mixed drift. See `docs/DESIGN.md`, sections 6.7 and 6.7b.
- The heuristic mis-matches 6.4% of deleted targets on one held-out benchmark seed, and it relocates only 33% of targets when the id, text and place all change (`docs/DESIGN.md`, sections 6.6 and 6.9). This is why a relocation needs verification before it is released.
- `pw edit` is tested in headless Chromium, through the real overlay script. A headed session has not been tested here.
- Nothing ran on Kaggle, and Kaggle's rules on multiple accounts are not confirmed. See `docs/KAGGLE.md`.
- The general developer corpus is not built. See `docs/KAGGLE.md`.

## Language note

Everything in the CLI, proxy, core, data generation, coordinator and launcher is Rust. Two exceptions are required by the platform:

- The in-page runtime and editor are JavaScript, because browsers run JavaScript or WebAssembly. The runtime is small, and it is the only code visitors run.
- Training is Python (PyTorch), which the brief allows. The shared starting point, the tokenizer and the weights are plain files that Rust reads.

Browser automation uses Microsoft's Playwright driver through the `playwright-rs` bindings.
